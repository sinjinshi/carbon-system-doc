
前端项目架构通常要提供这些**基建能力**：

## 1. 工程基建

| 能力            | 说明                                         |
| ------------- | ------------------------------------------ |
| 项目目录规范        | apps、packages、modules、components、utils 等分层 |
| Monorepo 管理   | pnpm workspace / turbo / nx                |
| TypeScript 规范 | 类型约束、路径别名、公共类型包                            |
| 构建配置          | Vite / Next.js / Webpack 配置                |
| 环境变量管理        | dev / test / staging / prod                |
| 代码规范          | ESLint、Prettier、Stylelint                  |
| Git 规范        | commitlint、husky、lint-staged               |
| CI/CD         | 自动检查、构建、测试、发布                              |

## 2. 请求与数据基建

| 能力         | 说明                                 |
| ---------- | ---------------------------------- |
| 请求封装       | axios / fetch wrapper              |
| Token 注入   | 自动携带 Access Token                  |
| 401 处理     | 刷新 Token、跳转登录                      |
| 错误处理       | 统一错误码、Toast、异常页面                   |
| Loading 管理 | 全局 loading / 局部 loading            |
| API 类型生成   | OpenAPI → TypeScript 类型            |
| Mock 服务    | MSW / mock server                  |
| 缓存策略       | React Query / SWR / TanStack Query |

## 3. 登录与权限基建

| 能力         | 说明                              |
| ---------- | ------------------------------- |
| 登录态管理      | 当前用户、租户、组织、角色                   |
| 路由守卫       | 未登录跳登录、无权限跳 403                 |
| 菜单权限       | 后端返回菜单，前端渲染                     |
| 按钮权限       | `permissionCode` 控制操作按钮         |
| 数据权限       | 租户、组织、设备组等上下文                   |
| Token 生命周期 | Access Token / Refresh Token 配合 |

## 4. UI 与交互基建

| 能力      | 说明                               |
| ------- | -------------------------------- |
| 组件库     | shadcn / antd / 自研组件             |
| 主题系统    | 明暗模式、品牌色、CSS Variables           |
| 布局系统    | Admin Layout、Sidebar、Header、Tabs |
| 表单体系    | React Hook Form + Zod            |
| 表格体系    | 查询、分页、排序、筛选、列配置                  |
| 弹窗体系    | Modal、Drawer、Confirm             |
| 空状态/错误态 | Empty、ErrorBoundary、Skeleton     |
| 图标体系    | iconfont / lucide / svg 管理       |

## 5. 路由与页面基建

| 能力              | 说明                     |
| --------------- | ---------------------- |
| 路由规范            | 页面目录、动态路由、嵌套路由         |
| 面包屑             | 根据路由/菜单自动生成            |
| 标签页             | 多页签、关闭、刷新、缓存           |
| 页面缓存            | keep-alive / tab cache |
| 404 / 403 / 500 | 标准异常页                  |
| 页面标题            | 自动设置 title             |
| 动态菜单            | 后端菜单驱动路由               |

## 6. 国际化基建

| 能力        | 说明                    |
| --------- | --------------------- |
| 多语言包      | zh-CN / en-US / ja-JP |
| 语言切换      | 切换后持久化                |
| 日期时间格式    | 时区、格式化                |
| 数字/金额格式   | 千分位、币种、精度             |
| 表单校验文案    | Zod / i18n 联动         |
| 缺失 key 检查 | 防止页面显示异常              |

## 7. 安全基建

| 能力      | 说明                                  |
| ------- | ----------------------------------- |
| XSS 防护  | 避免危险 HTML                           |
| CSP 适配  | script/style/img/font/connect/frame |
| CSRF 防护 | Cookie 模式下尤其需要                      |
| 敏感信息隔离  | 不把密钥打进前端包                           |
| 上传安全    | 类型、大小、后缀校验                          |
| 权限兜底    | 前端只做体验，后端必须强校验                      |

## 8. 测试基建

| 能力       | 说明                   |
| -------- | -------------------- |
| 单元测试     | Vitest / Jest        |
| 组件测试     | Testing Library      |
| E2E 测试   | Playwright           |
| Mock API | MSW                  |
| 测试数据     | fixtures / factories |
| 测试 ID 规范 | `data-testid`        |
| 覆盖率检查    | coverage gate        |

## 9. 质量与可观测性

| 能力            | 说明             |
| ------------- | -------------- |
| 错误监控          | Sentry         |
| 性能监控          | Web Vitals     |
| 日志上报          | 前端行为日志、接口错误    |
| 埋点体系          | 页面访问、按钮点击、业务事件 |
| Source Map 管理 | 线上问题定位         |
| 灰度发布          | 按租户/用户/环境开关    |
| Feature Flag  | 功能开关           |

## 10. 业务通用基建

| 能力     | 说明                |
| ------ | ----------------- |
| 租户上下文  | 当前租户、组织、门店、设备组    |
| 文件上传   | OSS/S3 上传、进度、断点续传 |
| 导入导出   | Excel/CSV 模板、任务进度 |
| 字典枚举   | 状态、类型、业务码统一管理     |
| 通知系统   | 站内信、消息提醒          |
| 审计日志入口 | 操作记录、变更记录         |
| 任务中心   | 异步任务、导出任务、批量操作    |

## 推荐优先级

### P0：必须先有

请求封装、登录态、权限、路由、Layout、环境变量、代码规范、表单、表格、错误处理。

### P1：中后台强烈建议

国际化、动态菜单、按钮权限、Mock、测试、上传、导入导出、字典枚举、异常页、主题。

### P2：规模化后补齐

监控埋点、Feature Flag、灰度发布、页面缓存、微前端/多应用集成、自动化测试覆盖率门禁。

一句话总结：

**前端架构基建的目标不是把项目搞复杂，而是把“请求、权限、路由、表单、表格、布局、规范、测试、发布”这些重复能力标准化，让业务页面只关心业务。**



后端项目架构如果按**轻量化生产可用**来设计，不需要一开始就上微服务，但至少要有这些基建能力：

## 1. 工程基建

| 能力         | 轻量化要求                                          |
| ---------- | ---------------------------------------------- |
| 目录分层       | `modules / common / config / prisma / scripts` |
| TypeScript | 全项目强类型                                         |
| 环境变量       | `.env` + schema 校验                             |
| 代码规范       | ESLint / Prettier                              |
| Git Hook   | 提交前跑 lint / typecheck                          |
| 构建部署       | Dockerfile + health check                      |
| 日志目录       | 区分 app log / error log / access log            |



## 2. 配置基建

必须有统一配置入口：

```ts
config/
  app.config.ts
  db.config.ts
  redis.config.ts
  jwt.config.ts
  oss.config.ts
```

生产最低要求：

| 配置项        | 要求                         |
| ---------- | -------------------------- |
| 数据库连接      | 只从 env 读取                  |
| JWT Secret | 不能写死                       |
| Redis 地址   | 从 env 读取                   |
| 上传配置       | endpoint / bucket / region |
| CORS       | 按环境配置白名单    （公共服务）               |
| 限流参数       | 可配置                        |

## 3. API 基建

| 能力              | 说明                                 |
| --------------- | ---------------------------------- |
| 统一响应结构          | `{ code, message, data, traceId }` |
| 全局异常处理          | 不把内部错误直接暴露给前端                      |
| 请求参数统一处理格式          |                    |
| 参数校验            | DTO + class-validator / zod        |
| 接口版本            | `/api/v1/...`                      |
| Swagger/OpenAPI | 给前端和 AI 生成类型                       |
| 请求日志            | method、path、status、duration        |
| traceId         | 每个请求一个链路 ID                        |

## 4. 认证基建

轻量生产建议：

| 能力                     | 要求                 |
| ---------------------- | ------------------ |
| ✅Access Token           | 30 分钟 ttl            |
| ✅密码加密                   | bcrypt / argon2    |
| 登录失败限制                 | 防暴力破解              |
| ✅会话存储                   | Redis 或 DB         |
| ✅登出                     | 清理 refresh session |

最小流程：

```text
login
  -> 校验账号密码
  -> 生成 accessToken + refreshToken
  -> 保存 refresh session
  -> 返回 token

request
  -> 校验 accessToken
  -> 注入 userId / tenantId / role

refresh
  -> 校验 refreshToken
  -> 旋转生成新 refreshToken
  -> 旧 refreshToken 失效
```

## 5. 权限基建


轻量化不要一开始做太复杂，但要预留能力：

| 能力   | 要求                        |
| ---- | ------------------------- |
| RBAC | 用户-角色-权限                  |
| 接口权限 | Controller / Handler 级别校验 |
| 菜单权限 | 返回前端菜单树                   |
| 按钮权限 | 返回 permission codes       |
| 租户隔离 | 所有业务表带 `tenantId`         |
| 数据范围 | 至少支持本人/本组织/全部             |

建议权限码：

```ts
device.manage
device.read
device.update
merchant.create
tenant.user.manage
```

不要只靠前端隐藏按钮，后端必须校验。

## 6. 数据库基建

| 能力        | 轻量化要求                                           |
| --------- | ----------------------------------------------- |
| ORM       | Prisma / TypeORM                                |
| Migration | 迁移文件必须进 Git                                     |
| Seed      | 初始化管理员、角色、权限                                    |
| 事务        | 关键写操作使用 transaction                             |
| 软删除       | 重要业务表建议 `deletedAt`                             |
| 审计字段      | `createdAt / updatedAt / createdBy / updatedBy` |
| 分页规范      | page/pageSize 或 cursor                          |
| 索引规范      | tenantId、状态、时间、外键字段                             |

生产最低要求：

```text
不要直接改生产库结构
不要删除已经上线的 migration
上线前跑 migrate deploy
```

## 7. 缓存与 Redis 基建

轻量生产常用 Redis 做这些：

| 场景              | 说明        |
| --------------- | --------- |
| Refresh Session | 存登录会话     |
| 验证码             | 短期验证码     |
|2fa | 2fa |
| 限流              | IP / 用户维度 |
| 幂等键             | 防重复提交     |
| 热点缓存            | 字典、菜单、权限  |
| 分布式锁            | 少量关键任务场景  |

一开始不用滥用缓存，优先保证数据库模型清晰。

## 8. 安全基建

| 能力         | 最低要求                       |
| ---------- | -------------------------- |
| CORS 白名单   | 不能生产全开 `*`                 |
| Helmet     | 基础安全头                      |
| Rate Limit | 登录、验证码、敏感接口                |
| 参数校验       | 防脏数据                       |
| SQL 注入防护   | 使用 ORM 参数化                 |
| 文件上传校验     | 类型、大小、后缀                   |
| 敏感日志脱敏     | token、password、secret 不入日志 |
| HTTPS      | 生产必须                       |
| Secret 管理  | env / 平台密钥管理               |

## 9. 文件上传基建

| 能力        | 说明                         |
| --------- | -------------------------- |
| 文件大小限制    | 例如 10MB / 100MB            |
| MIME 校验   | 不只看后缀                      |
| 上传目录规范    | tenant/date/type           |
| OSS/S3 适配 | 本地开发 + 云存储生产               |
| 预签名上传     | 大文件推荐                      |
| 文件记录表     | fileId、url、size、mime、owner |
| 权限校验      | 只能访问自己的租户文件                |

## 10. 任务与异步基建

轻量化不一定马上上 MQ，可以这样：

| 阶段  | 方案                     |
| --- | ---------------------- |
| 初期  | BullMQ + Redis         |
| 更轻量 | 定时任务 + DB 状态表          |
| 后期  | RabbitMQ / Kafka / 云队列 |

适合异步化的业务：

```text
批量导入
批量导出
设备批量操作
消息通知
报表生成
文件处理
```

## 11. 日志与可观测性

轻量生产至少要有：

| 能力           | 说明                       |
| ------------ | ------------------------ |
| 请求日志         | 谁请求了什么                   |
| 错误日志         | stack trace 记录到文件/平台     |
| 操作日志         | 谁改了什么业务数据                |
| 慢接口日志        | 超过阈值记录                   |
| traceId      | 前后端联动排查                  |
| health check | `/health`                |
| metrics 预留   | 后面接 Prometheus / Grafana |

最少要能回答：

```text
哪个用户在什么时候操作了什么？
哪个接口报错了？
为什么前端请求失败？
某个请求耗时在哪里？
```

## 12. 部署运维基建

轻量生产建议：

| 能力                | 要求                    |
| ----------------- | --------------------- |
| Dockerfile        | 统一构建                  |
| docker-compose    | 本地/小规模部署              |
| Health Check      | 服务健康检查                |
| Graceful Shutdown | 优雅关闭                  |
| DB Migration      | 发布时执行                 |
| 多环境配置             | dev/test/staging/prod |
| 日志持久化             | 不随容器丢失                |
| 备份策略              | 数据库定期备份               |
| 回滚策略              | 镜像版本可回退               |

## 推荐轻量架构

```text
Next.js 前端
   |
   | HTTP API
   v
NestJS API Server
   |
   | Prisma
   v
PostgreSQL

NestJS API Server
   |
   v
Redis

NestJS API Server
   |
   v
OSS / S3
```

如果业务还没很大，建议先用：

```text
单体 NestJS + PostgreSQL + Redis + OSS
```

不要一开始就上：

```text
微服务
Kafka
复杂网关
服务发现
K8s
分布式事务
```

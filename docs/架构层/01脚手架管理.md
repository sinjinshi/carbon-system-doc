# 脚手架项目结构和如何使用

> 缺点： 
> 
> 1. 调试, 修改困难, 需要脚手架维护人员参与
> 2. 对所有项目的影响难以评估

##  生成新项目

  - 通过互动式的脚本选择需要依赖的内容
    - 需要什么公共业务组件
    - 集成通用页面
      - 登录
      - 用户
      - 角色
      - 权限
  - 将依赖和业务注入到项目的lib下
  - claude.md 描述 项目的规范和公共业务组件的使用方法
  - next.config.js 通用配置 根据选项更新配置

## 更新项目依赖

- 通过获取脚手架的更新日志， 丢给项目的 ai,自动更新 依赖版本并进行适配

## 维护脚手架

将可复用的公共业务吸收至脚手架中

需要维护以下内容

1. 库使用说明 （提供给ai 调用）
2. 业务的更新日志 （日常维护）
3. break api 声明 （破坏性更新）
4. peer dependce 依赖声明 （解决交叉依赖问题）
